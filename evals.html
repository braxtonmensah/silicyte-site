Silicyte builds evaluation tasks for AI systems in therapeutic and basic biology. Every task comes with a key a program scores, a deterministic grader, controls that must fail, and a log of attempts to fool the grader.

A free sample of 4 tasks is public on GitHub and graded in GitHub Actions on every push: github.com/braxtonmensah/silicyte-bio-evals-sample. Read the graders, run them, try to break them.

Checkable task data is not a new idea: established data vendors already sell verified tasks. The sample is here so you can judge our work by its controls and its reward-hack logs, not by our description of them.

01 What a checkable task is

One right answer, and a grader that cannot be talked into another.

A model learns whatever its scorer rewards. In Silicyte’s own published research, deliberately degrading a design loop’s scoring model made its reported gain 2.4 times larger (t = -14.60, DOI 10.5281/zenodo.23441786). So each task we ship carries six things, and CI checks all six:

  1. A prompt with the conventions written out. Which atoms count, which annotations to drop, which edges to follow: written down, so there is exactly one right answer.
  2. A key a program scores. Rebuilt from the source data on every CI run; CI fails if the rebuilt key differs from the committed one by a single byte.
  3. A deterministic grader. No model calls, no randomness, no network. Same answer, same verdict, every time.
  4. Controls that must fail. Shuffled labels, plus the near-miss answer each common convention error produces.
  5. A reward-hack log. Attempts to fool the grader and whether each was caught, generated from the grader’s actual verdicts.
  6. Provenance. Every data file’s URL, license and SHA-256, checked on every run. CC0 and CC BY 4.0 sources only in the sample.

In total, 19 of 19 controls fail and 45 of 49 reward-hack attempts are caught. The 4 that are not caught are the same attempt, once per task, listed on purpose: copying the public key. A public sample cannot hide its key, and two of the four use labels that are public in MaveDB and UniProt. Paid tasks keep keys private and can use unpublished data.

What the near-miss controls show: in the GO task, keeping electronically inferred annotations moves the universe from 16,846 genes to 17,478, and following “regulates” edges moves the tested-term count from 7,149 to 7,419. In the HER2 task, selecting atoms by chain letter alone adds 3 water molecules that carry chain ID C. One convention error, one FAIL.

Source: CI run 40433262658, files tasks/*/key_meta.json and tasks/*/REWARD_HACK_LOG.md in the repository.

Break them yourself: the Grader Wargame turns these graders into levels with one deliberate hole each, plus a final level that runs the GO grader on a key kept off the repository. You attack by pull request; CI verifies every claim without running your code and writes the scoreboard.

03 How hard

Two of four stumped a frontier model. Two did not.

We judged difficulty three ways. First, the two prediction tasks set their bar 0.10 above the best of four cheap baselines, fixed before any model was run. Second, the two exact tasks fail on any one convention error, as the controls above show. Third, we ran a blind test.

In the blind test, a Claude Opus 5.5 agent saw only each prompt and its inputs (no keys, no internet), could not run code, and wrote one solution script per task, which CI ran once. It passed 2 of 4. It reproduced the HER2 epitope and the GO enrichment exactly: those two tasks test exact execution of a written-out analysis rather than stump a frontier model, and the blind pass doubles as an independent check that each has one right answer. It failed the two prediction tasks: on PTEN it reached Spearman 0.590, above every cheap baseline but under the 0.66 bar, and its signal peptide script crashed before writing an answer. One model, one shot, no execution: an agent that can run code and retry will do better. Full record: DIFFICULTY.md.

05 Plain terms

What this page is, and is not.

The sample is free under MIT (code) and CC BY 4.0 (task text and keys); data files keep their source licenses. It is a sample, not a benchmark: four tasks say little about any model’s biology ability in general. We use AI tools in our own work, including to build these tasks, and say so; every number on this page comes from the CI run, not from our reading of it. If you find a grader bug, report it and it becomes a CI test case with your name on it.
