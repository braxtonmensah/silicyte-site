Recursive self-improvement, measured

Does AI self-improvement
actually compound?

AI systems now write the tools, prompts and code that their next round runs on. Most reported gains are chosen on the same tests they are reported on. Silicyte runs pre-registered, compute-matched tests of whether self-improvement compounds, seals the test set the loop never sees, and publishes the result either way.

Why we work this way / Earlier work

Our own best number
did not reproduce. We said so.

On one operator’s laptop fleet of Claude Code agents, a guardrail hook was absent on 29.8% of the 103,850 calls it existed to check (53.1% with 11 or more agents at once), and a one-dispatcher fix brought that to 5 of 8,055. We then reran the load on clean public machines, with antivirus on and off and with the same shell layer: absence at the documented budget was 0.0000 in every cell up to 24 agents. The effect belongs to that laptop, not to agent fleets in general, so we stopped building a company on it. The probe and every load-test result stay public.
